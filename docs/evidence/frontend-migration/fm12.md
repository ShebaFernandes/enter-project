## Route and rollback boundary

The exact route is `/tenants/{tenant_id}/recruiter/organization/`. Its
independent process-only development flag is `recruiter-organization-page`.
The committed default remains empty/off. With the flag off Django renders the
existing legacy organization page; with it on Django renders the React page at
the same URL. Turning the flag off requires no data migration or replay.

The server bootstrap contains only version, page, tenant ID and
`requiresSession`. Organization data is loaded only after the shared client has
verified the session. Django reauthorizes every request, including tenant and
recruiter-role boundaries. Protected data is held in React memory only and the
page uses neither localStorage nor sessionStorage. React and legacy JavaScript
never own the same DOM subtree.

## Organization flow

1. `OrganizationPage` loads existing business-unit, opening,
   recruiter-entered-candidate and saved-search projections for the current
   tenant.
2. `BusinessUnitEditor` creates tenant-scoped organization context without
   presenting a business unit as a separate security boundary.
3. `OpeningEditor` creates an internal draft. Each `PublicationPanel` keeps the
   internal opening lifecycle separate from public publication, requires a
   fresh preview and explicit confirmation, and sends the server ETag on state
   or publication changes. HTTP 409 leaves server state untouched and asks the
   recruiter to preview again.
4. `SyntheticCandidatePanel` requires an explicit synthetic-data confirmation.
   It explains that these fixtures cannot contain real contact details or
   resumes and cannot merge with candidate-controlled profiles. The backend's
   immutable `RECRUITER_ENTERED_SYNTHETIC` provenance remains authoritative.
5. `SavedSearchManager` submits only a name and owned search ID. Opening context
   is restored from the authoritative saved search definition and cannot be
   independently supplied by the browser.

All writes use the shared same-origin client, session cookie, CSRF token,
trusted tenant header and idempotency key. No new API, model, migration,
authorization rule, audit action, outbox operation or worker was introduced.
