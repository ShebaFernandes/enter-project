The single pytest skip is the existing PostgreSQL audit-control case that cannot construct an intentionally tampered fixture because the database trigger correctly rejects it.

The first full pytest attempt overlapped a frontend build that atomically replaced `static/dist`; seven route checks therefore observed the intentional fail-closed legacy renderer. The deterministic rerun was performed after the build completed and passed 368/369 with the documented existing skip. This was test orchestration, not an application defect.

Authenticated Playwright runs use one-time local bootstrap tokens and Valkey-backed rate limits. Parallel servers originally shared Valkey database 0, causing genuine `429` responses and token/cache mismatches. Each retry paired its bootstrap command and server with an isolated Valkey database. This preserves the same authentication and rate-limit behavior while preventing unrelated test servers from consuming one another's local test state. All affected scenarios then passed.

## Accessibility, responsive and visual evidence

The authenticated baseline manifest contains 26 states: 14 production states and 12 immutable mockup reference states. Each state was checked at:

- 1440×1000 at 100% CSS zoom
- 1024×768 at 100% CSS zoom
- 390×844 at 100% CSS zoom
- 320×844 at 100% CSS zoom
- 1440×1000 at 200% CSS zoom

This produced 130 screenshots. Automated axe checks found zero serious or critical violations in the recorded states. Keyboard behavior, focus handling, accessible names, landmarks, dialogs and status announcements are exercised by the phase browser tests. Physical screen-reader, high-contrast and touch-device review remains a Phase 10 manual gate.

The complete capture index is in [FM14 screenshot manifest](./fm14/screenshot-manifest.md). Five additional live public-jobs captures are under `fm14/fm3-live/`.

One 320-pixel mockup comparison initially differed by 97 pixels (0.01 ratio) and passed unchanged when rerun in isolation; no golden was updated for that rendering flake. FM7 live screenshots were refreshed by the authenticated run because their synthetic note/status timestamps and records are intentionally current; no production visual expectation was weakened.

Intentional differences from the static mockup remain documented: production uses the approved text wordmark and system font stack, never fabricates candidate/business data, adds required privacy and security controls, and adapts rights and governance screens that have no direct mockup equivalent.

## Security and behavior retained

The complete regression suite retains session authentication, CSRF, tenant scoping, authorization, disclosure revalidation, encrypted notes, audit behavior, ETag/idempotency semantics, deterministic comparison and `SHORT_TENURE` non-interference. Tenant Admin governance does not grant automatic candidate access, and audit reads remain auditable.
