## Route and rollback boundary

The exact route is `/tenants/{tenant_id}/admin/governance/`. Its independent
process-only development flag is `tenant-governance-page`. The committed default
remains empty/off. With the flag off Django renders the existing legacy page;
with it on Django renders the React page at the same URL. Turning the flag off
requires no data migration, review replay or audit mutation.

Django authorizes an active Tenant Admin membership before rendering. The
bootstrap contains route context plus the same minimized active emergency-grant
metadata already supplied to the legacy page. It contains no candidate content.
All API requests are made only after the shared client verifies the session and
are reauthorized by Django. Protected state remains in React memory; neither
localStorage nor sessionStorage is used. React and legacy JavaScript never own
the same DOM subtree.

## Governance flow

1. `GovernancePage` provides accessible Overview, Audit metadata, Access reviews
   and Emergency access tabs, including arrow/Home/End keyboard movement.
2. `RedactedAudit` lazily calls the existing audit endpoint. It shows only the
   approved administrative projection. Successful, denied and failed reads stay
   server-audited; a failed UI read displays no cached copy.
3. `AccessReviewList` creates membership, privileged-role, purpose-grant,
   emergency-grant or audit-access reviews using CSRF and idempotency protection.
4. `ReviewDecision` requires a decision for every pending assignment. Retain,
   revoke and bounded-exception choices are explicitly confirmed. Exceptions
   require an active owner and future expiry; Django remains authoritative for
   that validation. Completion sends the current ETag, and HTTP 409 applies no
   decisions before reloading current evidence.
5. `EmergencyAccessPanel` exposes only reason code, operation/field scope, object
   count, status and expiry. Revocation has a non-mutating cancel path and an
   explicit destructive confirmation. It never grants candidate-content access.

All writes use the shared same-origin session client, CSRF token, trusted tenant
header and idempotency key. No new API, model, migration, authorization rule,
audit action, outbox operation or worker was introduced.
